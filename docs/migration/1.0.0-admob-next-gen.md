# Migration: AdMob Android → GMA Next-Gen SDK (1.0.0, 2026-10-08)

`unified_ads_admob` on **Android** now uses the **GMA Next-Gen SDK**
(`com.google.android.libraries.ads.mobile.sdk:ads-mobile-sdk:1.5.0`) instead of the legacy Google Mobile Ads SDK
(`com.google.android.gms:play-services-ads`). Google has put the legacy SDK in maintenance mode, while Next-Gen is
supported until at least Q1 2028.

**iOS is unchanged.** It still uses `Google-Mobile-Ads-SDK` 13.11.0, because Next-Gen is Android-only.

## What doesn't change

- **The Dart API.** Your `AdConfig`, `NetworkConfig`, ad classes, callbacks and `AdmobConsentProvider` code stays the
  same.
- **The manifest App ID.** `com.google.android.gms.ads.APPLICATION_ID` meta-data is **still required** in
  `AndroidManifest.xml`, because the UMP consent SDK reads it.
- **minSdk 24** and UMP 4.0.0.

## What changes

| Area | Before (legacy) | Now (Next-Gen) |
|---|---|---|
| App ID | read from the manifest by the SDK | also passed in code at init: the adapter passes the manifest value, so set `NetworkConfig.appId` to the same ID (a mismatch is logged) |
| `AdError.nativeCode` (Android) | integers such as `"3"` (no fill) | enum names such as `"NO_FILL"`, `"NETWORK_ERROR"`, `"APP_NOT_FOREGROUND"` |
| `AdErrorCode` mapping | — | the same categories; `TIMEOUT` now maps to `AdErrorCode.timeout` (it was `internal`) |
| New formats | — | rewarded interstitial and app open (both platforms) |

If you match on `AdError.nativeCode` for AdMob on Android, switch to the enum names in the table above.

## Required only when another dependency pulls the legacy SDK

The two SDKs **cannot be in the same app**; their duplicate classes break the build. If any other dependency brings in
`play-services-ads`, exclude it in your app's `android/app/build.gradle.kts`. Common cases:

- the official `google_mobile_ads` Flutter plugin;
- Google's mediation adapters, such as the Meta bidding adapter (see `docs/setup/admob.md`);
- another ads SDK that bundles it.

```kotlin
configurations.configureEach {
    exclude(group = "com.google.android.gms", module = "play-services-ads")
    exclude(group = "com.google.android.gms", module = "play-services-ads-lite")
}
```

Google's mediation adapters work with Next-Gen through this exclusion, as described in Google's Next-Gen mediation guide.
The official `google_mobile_ads` plugin calls the legacy APIs directly, so it **can't** be used alongside
`unified_ads_admob`. Use one or the other.

## Verifying

`tool/verify_opt_in.sh android` fails if the legacy `play-services-ads` artifact is resolved anywhere in the app's
release classpath.

These packages were unpublished when this change was made (before 1.0.0), so no released version used the legacy SDK.
