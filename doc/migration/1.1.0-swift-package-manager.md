# Migration: iOS CocoaPods → Swift Package Manager only (1.1.0, 2026-10-12)

From **1.1.0**, every `unified_ads` package builds on iOS **only** through Swift Package Manager (SPM). The podspecs
are gone, so an app that still builds its plugins with CocoaPods can't link `unified_ads` on iOS.

This ships as a **minor** version, so a `^1.0.0` constraint picks it up on the next `flutter pub upgrade`. If you
can't enable SPM yet, pin `1.0.x` (for example `unified_ads: '>=1.0.0 <1.1.0'`) until you can.

**Android is unchanged.** **The Dart API is unchanged.** Your `AdConfig`, `NetworkConfig`, ad classes, callbacks and
consent code stay the same; only the iOS build integration moves.

## Why

- Flutter's SPM integration is on by default on stable since Flutter 3.44, and Flutter is moving plugins off CocoaPods.
- Every vendor now ships an official Swift package. Unity Ads, Start.io and InMobi were CocoaPods-only in 1.0.x and now
  have one, so no adapter needs Flutter's mixed mode any more.
- Meta has said Audience Network 6.22 is the last CocoaPods release; later versions are SPM-only.
- One integration path instead of three (SPM, CocoaPods dynamic, CocoaPods static) to build, test and document.

## Requirements

| | Minimum |
|---|---|
| Flutter | **3.44** with SPM enabled (the default on stable; `flutter config --enable-swift-package-manager`) |
| Xcode | **26.2** |
| iOS deployment target | 13.0; **15.0** with `unified_ads_facebook` or any Meta bidding adapter |

## What changes

| Area | 1.0.x | 1.1.0 |
|---|---|---|
| iOS distribution | CocoaPods podspec (+ `Package.swift` for admob, applovin, ironsource, facebook, core) | `Package.swift` **only**, in every package |
| How opt-in linking works | `flutter_install_all_ios_pods` adds a pod only for plugins the app depends on | `FlutterGeneratedPluginSwiftPackage` adds a local package only for plugins the app depends on; each adapter's `Package.swift` declares its vendor SDK |
| Deployment target | `platform :ios, '…'` in `ios/Podfile` | **Runner** target / project `IPHONEOS_DEPLOYMENT_TARGET` in Xcode |
| Meta bidding (admob / applovin / ironsource) | a `pod '…'` line in the Podfile | a Swift package added to the Runner target in Xcode |
| Verification lock file | `ios/Podfile.lock` | `ios/Runner.xcworkspace/xcshareddata/swiftpm/Package.resolved` |
| Privacy manifest bundle | `<package>_privacy.bundle` | the SPM resource bundle `<package>_<package>.bundle` (contents unchanged) |

## Steps

1. **Upgrade Flutter and Xcode** to the versions above (`flutter --version`, `xcodebuild -version`).
2. **Enable SPM** if you turned it off:

   ```bash
   flutter config --enable-swift-package-manager
   ```

   Also check that `pubspec.yaml` has no `flutter: config: enable-swift-package-manager: false` override.
3. **Bump every `unified_ads` dependency to `^1.1.0`** in `pubspec.yaml` (core, platform interface if you use it
   directly, and each adapter), then run `flutter pub get`.
4. **Remove CocoaPods if nothing else needs it.** If every plugin in your app supports SPM:

   ```bash
   cd ios
   pod deintegrate
   rm -rf Pods Podfile Podfile.lock
   ```

   If **other** plugins in your app are still CocoaPods-only, keep the `Podfile`. Flutter's mixed mode still builds
   those plugins through CocoaPods; only the `unified_ads` packages must come through SPM. Remove any manual
   `pod '…'` lines you added for unified_ads networks (vendor SDKs or Meta bidding adapters) so the same SDK is not
   linked twice.
5. **Set the deployment target in Xcode.** Open `ios/Runner.xcworkspace`, select the **Runner** project and the
   **Runner** target, and set **iOS Deployment Target** (`IPHONEOS_DEPLOYMENT_TARGET`) to **13.0**, or **15.0** if you
   use `unified_ads_facebook` or a Meta bidding adapter. A `platform :ios` line in a remaining Podfile no longer
   governs the unified_ads packages.
6. **Move Meta bidding to SPM** (only if you used it). Delete the pod line and add the package to the **Runner** target
   with **File > Add Package Dependencies…**:

   | Mediation | Removed pod line | Swift package | Rule | Product |
   |---|---|---|---|---|
   | AdMob | `pod 'GoogleMobileAdsMediationFacebook'` | `https://github.com/googleads/googleads-mobile-ios-mediation-meta` | **Commit** `0a3d0597402162334fb5e11816ca612478180095` (= tag `6.22.000`, which is not valid semver) | `MetaAdapterTarget` |
   | AppLovin MAX | `pod 'AppLovinMediationFacebookAdapter'` | `https://github.com/AppLovin/AppLovin-MAX-Swift-Package-Meta` | Exact `6220100.0.0` | `AppLovinMediationFacebookAdapter` |
   | LevelPlay | `pod 'IronSourceFacebookAdapter'` | `https://github.com/ironsource-mobile/LevelPlay-Facebook-Adapter-Swift-Package` | Exact `5.6.0` | `FacebookAdapter` (brings `FBAudienceNetwork` 6.22.1) |

   Meta bidding needs iOS 15.0 (step 5). The adapters still detect it at runtime and log it at init.
7. **`-ObjC`.** The `unified_ads_inmobi` and `unified_ads_ironsource` manifests pass `-ObjC` to the linker
   (⚠ to be confirmed by CI). If you get unrecognized-selector crashes or missing-category errors from InMobi or
   LevelPlay, add `-ObjC` to **Runner → Build Settings → Other Linker Flags**.
8. **Clean and rebuild:**

   ```bash
   flutter clean
   flutter pub get
   flutter build ios --no-codesign
   ```

## Verifying

- In Xcode, **Package Dependencies** lists only the vendor packages of the adapters you depend on.
- `ios/Runner.xcworkspace/xcshareddata/swiftpm/Package.resolved` contains only those vendor packages.
  `tool/verify_opt_in.sh ios` checks this after resolving packages with `xcodebuild -resolvePackageDependencies`.

## Troubleshooting

- **A "plugin does not support Swift Package Manager" / "Swift Package Manager is disabled" style error, the build
  falls back to CocoaPods, or `pod install` can't find a `unified_ads` podspec.** SPM is disabled for this project
  or Flutter is older than 3.44. Upgrade Flutter, run `flutter config --enable-swift-package-manager`, remove any
  `enable-swift-package-manager: false` in `pubspec.yaml`, then `flutter clean`.
- **Package resolution fails or hangs.** Check network access to `github.com`, then in Xcode use
  **File > Packages > Reset Package Caches**, or delete `~/Library/Developer/Xcode/DerivedData` and rebuild.
- **"compiling for iOS 13.0, but module 'FBAudienceNetwork' has a minimum deployment target of iOS 15.0".** Raise
  the Runner target's deployment target to 15.0 (step 5).
- **Duplicate symbols or the same SDK linked twice.** A leftover Podfile still pulls a vendor SDK or a Meta bidding pod.
  Remove the pod line (step 4) and run `pod install` for the remaining pods.
- **Undefined symbols / unrecognized selector from InMobi or LevelPlay.** Add `-ObjC` to Other Linker Flags (step 7).

## Not supported any more

- CocoaPods builds of any `unified_ads` package, including `use_frameworks!` / `:linkage => :static` variants.
- Single-package mode on iOS ([`doc/single_package_mode.md`](../single_package_mode.md), a design that was never
  shipped): it relied on Podfile `ENV`, which SPM manifests can't read.

If you can't move to SPM yet, stay on the 1.0.x line.
